# Building Alp

## One-command setup

```bash
./scripts/setup.sh
```

Installs every Homebrew prerequisite, runs `tuist generate`, and prints
the next steps. Re-runnable; skips anything already in place.

If you'd rather do it by hand:

## Prerequisites

```bash
brew install gnupg           # GnuPG (required at runtime)
brew install swiftlint       # lint
brew install swiftformat     # format
brew install --cask tuist    # Xcode project generation
```

You need **Xcode 26 or 27** and an Apple ID (free or paid developer account).

## Configure Signing

Signing is automatic, but the Team ID is set in `Project.swift` (`DEVELOPMENT_TEAM`),
so a team picked in Xcode is overwritten by the next `tuist generate`. To build
under your own team, change it there and in `Shared/BuildConfig.swift` (`teamID`).
For releases, also change `scripts/ExportOptions.plist` and set `APPLE_TEAM_ID`
for `build-release.sh`.

## Generate & Build

```bash
# 1. Generate the Xcode project (not committed to git)
tuist generate

# 2. Open in Xcode
open Alp.xcworkspace

# 3. Build & Run the Alp scheme (⌘R)
```

Or build from the command line:

```bash
xcodebuild build \
  -workspace Alp.xcworkspace \
  -scheme Alp \
  -destination 'platform=macOS' \
  -configuration Debug
```

## First Run

1. In the running app, click **"Install Helper"** to register the helper.
   Debug builds use `SMAppService` exactly like release builds, so the helper shows
   up in System Settings → General → Login Items. Each build location registers its
   own record — click **"Uninstall Helper"** before moving or deleting a build.
   BTM pins the registration to the exact bundle, so after a rebuild the helper can
   fail to spawn (`launchctl print gui/$UID/app.alp.Alp.helper` shows exit code 78
   or "Invalid or missing Program") — uninstall and reinstall the helper to fix it.
   If reinstalling does not help, a reboot clears the stale record.
2. Open **Mail → Settings → Extensions** and enable **Alp**.
3. Compose a new message: Mail's sign/encrypt buttons and Alp's toolbar button
   should appear.

## Project Structure

```
Alp/                    Main app — settings UI + helper installer
AlpExtension/           Mail extension — MailKit protocols, compose toolbar
AlpHelper/              XPC helper (launch agent) — calls gpg binary (unsandboxed)
AlpPinentry/            Bundled pinentry — Assuan passphrase prompt for gpg-agent
Shared/                 Code shared by Alp, AlpExtension, AlpHelper, and tests
Tests/                  Unit tests (AlpTests)
Tests/LiveXPC/          Opt-in live-helper tests (AlpXPCTests)
scripts/                Setup, test, and release scripts
docs/                   Verification docs + update feed (GitHub Pages)
Project.swift           Tuist manifest (defines all targets and settings)
```

The `.xcodeproj` and `.xcworkspace` are generated by Tuist and **not committed** to git. Always regenerate after changing `Project.swift`.

## Releasing

Releases are **built and signed on a developer Mac** — no signing keys live in
CI. CI (`.github/workflows/`) only builds, tests, lints, and runs CodeQL.

Alp's updater is **notification-only** — there is no update framework and no
self-installing update path. Alp fetches a signed `release.json`, verifies an
Ed25519 signature with CryptoKit, and (on a newer version) points the user at
the notarized DMG download. Gatekeeper enforces install authenticity.

### One-time setup

You need an Apple Developer ID Application certificate (cert + private key in
your **login keychain**), an Apple Developer Program membership, and
`create-dmg` (`brew install create-dmg`).

**Notarization profile** — store an app-specific password in the keychain so
`notarytool` never sees it on the command line:

```bash
xcrun notarytool store-credentials alp-notary \
  --apple-id you@example.com --team-id 3G6WR6H4M5
```

**Ed25519 update key** — generate the keypair (CryptoKit, no dependencies):

```bash
swift -e 'import CryptoKit; let k = Curve25519.Signing.PrivateKey(); print("Private:", k.rawRepresentation.base64EncodedString()); print("Public: ", k.publicKey.rawRepresentation.base64EncodedString())'
```

1. Store the **Private** value in the keychain — `build-release.sh` reads it
   from there (or from `$ALP_UPDATE_PRIVATE_KEY` if set):
   ```bash
   security add-generic-password -a alp -s alp-update -w '<private-base64>'
   ```
2. Copy the **Public** value into `Alp/SupportingFiles/Info.plist` as the
   `AlpUpdatePublicKey` value. Commit it.

The private key never leaves your Mac. Lose it, lose the ability to sign
updates — keep an offline backup (not in the repo).

### Each release

Condense the `Unreleased` section of `CHANGELOG.md` into `RELEASE_NOTES` (it
becomes the `notes` field of `release.json`; without it the feed ships "Bug
fixes and improvements."), then move those entries under the new version
heading.

```bash
export DEVELOPER_ID_APPLICATION="Developer ID Application: Your Name (3G6WR6H4M5)"
export GPG_SIGNING_KEY=<fingerprint>    # required: detached signature on SHA256SUMS
RELEASE_NOTES="…" ./scripts/build-release.sh 0.9.5   # archives, signs, notarizes, staples, DMGs
gh release create v0.9.5 --prerelease build/Alp-0.9.5.dmg build/Alp-0.9.5.SHA256SUMS*
```

`build-release.sh` also writes `build/release.json` (version / minOS / download
URL / DMG sha256 / notes) and signs it into `build/release.json.sig`. Commit
both to `/docs` and push to `main` so GitHub Pages serves the feed at
<https://alp-gpg.github.io/alp/release.json>.

Every 0.x release is a **pre-release** (`--prerelease`) — drop the flag only
when 1.0 ships.
