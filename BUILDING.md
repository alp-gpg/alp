# Building Alp

## One-command setup

```bash
./scripts/setup.sh
```

Installs every Homebrew prerequisite, runs `tuist generate`, and prints
the next steps. Re-runnable; skips anything already in place.

If you'd rather do it by hand:

## Prerequisites

```bash
brew install gnupg           # GPG binary (required at runtime)
brew install swiftlint       # lint
brew install swiftformat     # format
brew install --cask tuist    # Xcode project generation
```

You need **Xcode 26** or later and an Apple Developer account (free or paid).

## Configure Signing

The project uses `CODE_SIGN_STYLE = Automatic`. When you open the workspace in Xcode, select your own Apple Developer team — Xcode will handle provisioning profiles automatically.

If you're building a fork for distribution, update `DEVELOPMENT_TEAM` in `Project.swift` and the `teamID` in `Shared/BuildConfig.swift` to match your Team ID.

## Generate & Build

```bash
# 1. Generate the Xcode project (not committed to git)
tuist generate

# 2. Open in Xcode
open Alp.xcworkspace

# 3. Build & Run the Alp scheme (⌘R)
```

Or build from the command line:

```bash
xcodebuild build \
  -workspace Alp.xcworkspace \
  -scheme Alp \
  -destination 'platform=macOS' \
  -configuration Debug
```

## First Run

1. In the running app, click **"Install Helper"** to register the background agent.
2. Open **Mail → Settings → Extensions** and enable **Alp**.
3. Compose a new message — the Sign/Encrypt toolbar should appear.

## Running Tests

```bash
# Via Xcode
# ⌘U with the Alp scheme selected

# Via command line
xcodebuild test \
  -workspace Alp.xcworkspace \
  -scheme Alp \
  -destination 'platform=macOS'
```

Tests require `gpg` installed and at least one secret key in your keyring. They dynamically discover the first available key — no configuration needed.

## Project Structure

```
Alp/                    Main app — settings UI + helper installer
AlpExtension/           Mail extension — MailKit protocols, compose toolbar
AlpHelper/              XPC helper agent — calls gpg binary (unsandboxed)
Shared/                 Code shared across all targets
Tests/                  Unit tests
Project.swift           Tuist manifest (defines all targets and settings)
```

The `.xcodeproj` and `.xcworkspace` are generated by Tuist and **not committed** to git. Always regenerate after changing `Project.swift`.

## Releasing (one-time update-key setup)

Alp's updater is **notification-only** — there is no Sparkle and no
self-installing update path. Alp fetches a signed `release.json`, verifies an
Ed25519 signature with CryptoKit, and (on a newer version) points the user at
the notarized DMG download. Gatekeeper enforces install authenticity. brew
users get updates from `brew upgrade --cask alp`.

**Once per project** — generate an Ed25519 keypair using CryptoKit (no
external dependencies):

```bash
swift -e 'import CryptoKit; let k = Curve25519.Signing.PrivateKey(); print("Private:", k.rawRepresentation.base64EncodedString()); print("Public: ", k.publicKey.rawRepresentation.base64EncodedString())'
```

1. Copy the **Private** value (base64, ~44 chars) into a GitHub secret
   named `ALP_UPDATE_PRIVATE_KEY`. This is what `scripts/build-release.sh`
   uses to sign `release.json` via `scripts/sign-release.swift`.
2. Copy the **Public** value into `Alp/SupportingFiles/Info.plist` as the
   `AlpUpdatePublicKey` value. Commit it.

The private key never leaves GitHub secrets. Lose it, lose the ability to
sign updates — store a backup somewhere safe (not in the repo).

**On every release**, `scripts/build-release.sh` writes `build/release.json`
(version / minOS / download URL / DMG sha256 / notes) and signs it into
`build/release.json.sig`. Commit both to `/docs` and push to `main` so GitHub
Pages serves the feed at <https://alp-gpg.github.io/alp/release.json>. Set
`GPG_SIGNING_KEY` to also emit a detached GPG signature on `SHA256SUMS`.
