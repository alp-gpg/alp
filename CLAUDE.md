# Guidance for AI coding agents

**[CONTRIBUTING.md](CONTRIBUTING.md) is the source of truth** — read it before changing
anything. This file is the short version plus the things agents most often get wrong.

## What Alp is

GPG for Apple Mail on macOS 26 — a **security tool** that handles private keys and
passphrases. Scope is deliberately narrow: if a change doesn't serve a Mail-PGP user,
it probably doesn't belong. When unsure, open an issue before writing code.

## Hard rules

- **Never leak secrets.** Don't log plaintext, passphrases, private keys, fingerprints,
  or email addresses. Keep `os_log` at default privacy.
- **Respect the sandbox boundary.** `AlpExtension` cannot call `Process()` or touch the
  filesystem — all gpg work goes through the XPC `AlpHelper`. See the target table in
  CONTRIBUTING.md.
- **Don't add dependencies.** Alp is intentionally dependency-light (the updater is
  in-house, not Sparkle). Reach for the standard library and platform APIs first.
- **Don't weaken** code signing, entitlements, or the gpg invocation boundary to make
  something build or a test pass. Ask instead.
- **Keyserver and WKD lookups are client-side, on purpose.** Alp fetches keys over
  `URLSession` (`Shared/KeyserverSession.swift`, `Shared/WKDClient.swift`) and only feeds
  the bytes to `gpg --import`. Do **not** switch to gpg's keyserver machinery
  (`--keyserver`, `--locate-keys`, `--auto-key-locate`) — client-side lookups keep network
  access auditable and insulate Alp from gpg keyserver-config changes (e.g. GnuPG 2.5
  dropped the built-in default keyserver).

## Before you finish

- The Xcode project is generated by Tuist. Edit `Project.swift`; **never commit**
  `*.xcodeproj` / `*.xcworkspace` (they're gitignored).
- Run and make clean: `swiftformat .` then `swiftlint --strict`. CI enforces both.
- Run tests (`xcodebuild test` or ⌘U). They need `gpg` and a key in the keyring.
- Add tests for any new GPG operation.
- Keep PRs focused — one logical change, with a clear description of what and why.
